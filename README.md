# 自主 Agent 平台

最终目标是建设一套可部署到医院或其他单位的通用自主 Agent 平台：接收用户需求，自主选择工具、执行操作、读取真实结果并继续判断，直到完成任务或达到退出条件，最后汇总反馈。通过配置模型、提示词、工具和业务范围创建不同 Agent，复用同一套执行能力。目标与分阶段计划维护在 [技术方案](AI_Agent_可视化工作流平台_技术方案_V1.md)。

## 最终目标与执行方式

- 服务端能力：请求业务接口、查询数据库、检索知识库、执行指定命令，并按需接入 MCP、Skill 等能力。
- 终端能力：支持安卓、鸿蒙等终端，通过终端执行器打开应用或页面、填写内容、执行已接入的操作，并回报真实结果。例如“打开患者查询，输入张三”。平台共用 Agent 决策，各终端分别适配执行能力。
- 自主执行内核：在一次任务中进行“模型决定下一步 → 调用工具 → 读取结果 → 再决定”的循环，保留本次模型与工具消息，根据真实结果判断任务是否完成。
- 可视化流程：一条保存的流程仍可承载一个 Agent，安排业务步骤、分支和汇总；自主执行节点负责内部多轮决策与工具调用。意图分析和任务分发按场景使用。
- 执行控制：后续支持最大执行步数、超时、重试、失败后停止或继续、失败分支和结果追踪；终端指令送达与操作完成分别记录。

以上为长期目标。当前实现以配置管理和固定流程为基础，业务接入先从只读查询开始；自主工具循环、真实业务工具、命令执行和终端执行器尚未实现。跨请求记忆后续再做。

## 工程与目录

web 和 agent 是两个独立工程，各自在自己的目录安装依赖、启动和使用 IDE 打开。

```text
web/                         Vue 3、TypeScript、Element Plus、Vue Flow
agent/                       Python 3.12+、FastAPI、SQLAlchemy
  app/core/                  配置、日志、异常和统一返回
  app/modules/               模型、提示词、流程配置管理及调试台
  app/workflow/              流程共用对象、运行组织和具体节点
  app/infrastructure/        数据库连接及 LangGraph、LangChain 接入
sql/                         PostgreSQL、MySQL 5.7+ 建表与初始化数据
docs/                        流程保存格式和示例
```

配置输入按原值提交与保存，数据库约束和框架基础要求仍生效。主要功能入口维护一份说明，子目录通过代码注释介绍；协作规则见 [后端](agent/AGENTS.md) 与 [前端](web/AGENTS.md)。

## 当前能力

- 模型、提示词、流程配置的基础增删改查；模型和提示词使用进程内按需缓存。
- 模型连接测试、无上下文的单轮问答；API Key 不回显。
- 全屏流程画布，支持开始、大模型、意图分析、收敛、返回节点，固定串行和并行连线。
- 节点独立选择直接或全部上游输入，提示词通过弹窗管理并点选变量；最终返回文字或 JSON，排查使用后端日志。
- 后端任务隔离运行入口：程序生成任务ID，每项任务独立保存状态，主图按任务ID汇总最终结果；当前尚未接入画布分发。

现有“开始 → 意图分析 → 返回”可用于确认离线模型的分类效果，示例见 [intent-analysis.json](docs/examples/intent-analysis.json)，模型ID按实际配置替换。下一步优先实现可复用的自主执行内核，以一个真实只读 HTTP 工具验证“自主选择调用 → 读取真实结果 → 汇总回答”，再逐步补充配置、失败策略、多任务和终端执行能力。
