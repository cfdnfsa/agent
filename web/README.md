# Web 前端

Vue 3 + TypeScript + Vite + Element Plus + Vue Router + Vue Flow。使用兼容 Vite 的 Node.js 版本（本机已使用 Node.js 24 验证）。

当前是个人极简版本：不主动做字段必填、长度、URL、枚举等业务校验，也不自动去空格。输入原样提交，失败时显示后端或 SDK 返回的公开说明；维护规则见 [AGENTS.md](AGENTS.md)。

在本目录执行：

```powershell
npm install
npm run dev
```

访问 http://localhost:5173 。执行 `npm run build` 进行类型检查并构建。

顶部导航切换“模型配置”“提示词配置”“流程配置”和“调试台”。页面使用 hash 路由：`/#/model-configs`、`/#/prompt-configs`、`/#/workflow-configs`、`/#/playground`，刷新子页面无需额外配置服务器回退规则。

## 调试台

选择已保存的模型，输入问题后发送，回答以聊天气泡完整展示。每次请求只提交模型配置ID和当前问题，不携带旧气泡中的消息，没有上下文记忆，也不保存聊天记录。切换模型、清空、导航离开或刷新页面会清除气泡。问题没有前端长度或空内容限制，不自动去空格，失败时保留输入供重试。

模型选择复用列表接口，分页读取全部已配置模型；没有模型时提示先到模型配置页添加。发送中禁止切换模型或重复发送，等待期间显示“正在回答”。

## 提示词配置管理

PromptConfigs.vue 提供提示词分页列表、新增、编辑、只读详情与删除确认，入口为 `/#/prompt-configs`。列表只显示 ID 和名称，编辑和详情通过详情接口单独读取正文；正文读取成功后才允许保存，读取失败可在弹窗内重试，避免概要中的缺失正文覆盖已有内容。

新增和编辑共用名称输入框、正文多行文本框；名称和正文原样提交，不增加必填、长度限制或自动 trim。保存失败保留输入，删除失败保留确认弹窗，删除末页最后一条后自动退回有效页码。模板在此统一维护，流程画布的各 LLM 节点可分别选用。

## 流程配置管理

WorkflowConfigs.vue 提供概要分页与删除确认，路径为 `/#/workflow-configs`。“新增流程”进入 `/#/workflow-configs/new`，“编排”进入 `/#/workflow-configs/{id}`，“详情”使用同一画布的只读模式。

WorkflowDesigner.vue 全屏显示 Vue Flow，工具箱和配置区可收起。提供开始、大模型、收敛、返回节点，新流程自带开始和返回节点，由用户连线；支持拖动、连线、缩放和删除。所有节点可在右侧修改名称，与 ID 分开保存，改名不影响连线；未填名称时画布显示类型名称，不增加重名、长度或 trim 限制。

LLM 节点右侧可选择模型和可选提示词，下拉列表分页读取全部提示词概要，名称后显示ID以区分同名模板。新节点默认不选提示词，允许清除；保存时仅写入 config.prompt_config_id，加载选项失败或引用记录未出现在列表时不自动改写已有选择。后端运行前通过缓存取得正文原样作为系统消息，公共 LangChain 模板把上游上下文填入用户消息；未选择提示词时只生成用户消息。

每个流程恰好一个开始和一个返回节点：已有时分别禁用重复点击、拖拽和添加，删除后可以重新添加，恰好各一个时才允许运行。返回节点只有输入圆点，不能连接下游，后端运行前再次检查唯一性和连线。最小可直接连接“开始 → 返回”，原样返回本次输入；模型流程连接“开始 → 大模型 → 返回”。

开始节点填写本次文字和可选用户ID，点击旁边的 ▶ 或右侧运行按钮。运行前自动保存当前画布，再以 `{"text":"你好","user_id":"user_001"}` 调用运行接口；user_id 可省略或为 null，仅预留在本次状态中。页面只显示最终文字、JSON 结果或错误，文字、用户ID和结果不随流程保存，刷新或离开后清除。已移除打印节点、步骤记录和调试面板；排查信息在后端日志查看。

从同一个节点可以分出多条支路，将需要合并的结果连到收敛节点，再接返回节点。LLM、收敛可选 config.input_scope：all_upstream 默认读取全部上游依赖链，direct_upstream 仅读取直接上游。例如要只用总结，就在使用总结的下游节点选择直接上游。全部原始结果统一保留，后续节点也能重新选择全部上游；无关分支不进入输入。返回节点只返回一个直接上游的最终业务结果，其他独立支路仍参与同步执行。跨请求历史、后台记忆和队列尚未实现。

流程定义顶层保存 start_node_id、return_node_id、nodes、edges。前两个ID由当前画布自动推导，按钮或键盘删除后保存为 null，重新添加后自动更新；未完成的草稿可保存，但运行需要两个节点都存在。后端直接读取这两个ID，并在整理关系时检查它们与实际节点一致。节点配置、扩展字段和坐标按当前定义读取与保存；缺少新字段的定义不自动迁移，可在原文区域修正。无法解析的原文保留供修正，不以空图覆盖。协议见 [最小流程定义](../docs/workflow-definition.md)。


## 模型配置管理

模型配置页提供列表、新增、编辑、删除确认和分页，每页默认 20 条。模型配置不维护创建时间、更新时间，列表不展示时间列。接入方式提供 OpenAI 兼容、Ollama、Anthropic、Google GenAI 常用选项，也允许手工填写；保存时不检查枚举，实际能否调用由对应集成决定。

每条配置的“测试”按钮调用 `POST /api/model-configs/{id}/test`，验证已保存的模型配置。测试期间显示加载状态并禁止重复操作；成功展示耗时，失败展示错误说明。它会发送真实模型请求，可能消耗少量额度，不保存测试历史，也不展示 Key 或模型原始回复。

表格、表单、弹窗、分页、加载状态与提示使用 Element Plus，已移除表单校验、必填标记和输入限制。组件通过 `unplugin-vue-components` 自动按需导入，不全量注册。`App.vue` 中的 Config Provider 统一设置中文。

API Key 不回显。编辑时留空保留原密钥，填写新值替换，勾选“清除已保存的 API Key”则提交 null。删除前需要确认；保存或删除失败时保留弹窗，显示错误后可以重试。请求进行中禁止重复提交和关闭操作弹窗。

先启动 Python 后端（默认 `http://127.0.0.1:8000`），再启动前端。页面请求 `/api/model-configs`、`/api/prompt-configs`、`/api/workflow-configs` 和 `/api/playground/chat`，由 `vite.config.ts` 的开发代理转发到后端。后端地址不同时修改代理目标即可；不需要添加后端跨域配置。

## 文件职责

| 文件 | 职责 |
|---|---|
| `src/App.vue` | 应用外壳、中文组件配置、页面入口 |
| `src/views/ModelConfigs.vue` | 模型配置页面、原样提交表单、分页及交互状态 |
| `src/views/PromptConfigs.vue` | 提示词概要分页、完整正文读取与增删改查 |
| `src/views/WorkflowConfigs.vue` | 流程列表、画布入口和删除确认 |
| `src/views/WorkflowDesigner.vue` | 全屏画布、模型选择、运行结果和保存还原 |
| `src/views/Playground.vue` | 模型选择与单轮问答接口装配 |
| `src/components/ChatPanel.vue` | 可复用的输入、消息气泡和发送状态 |
| `src/components/WorkflowCanvasNode.vue` | 通用节点卡片和连接圆点 |
| `src/components/workflowNodes.ts` | 工具箱节点目录和流程结构类型 |
| `src/router.ts` | 模型配置、提示词配置、流程配置和调试台页面路由 |
| `src/api/modelConfigs.ts` | 请求与响应类型、列表和增删改接口 |
| `src/api/promptConfigs.ts` | 提示词概要、详情、保存和删除接口 |
| `src/api/workflowConfigs.ts` | 流程概要、详情、保存、删除和运行接口 |
| `src/api/playground.ts` | 提交当前问题，取得回答 |
| `src/api/request.ts` | 共用 fetch 与统一响应处理 |
| `src/components.d.ts` | 自动生成的组件与指令类型声明，供 IDE 和类型检查使用 |
| `src/style.css` | 应用布局、主题颜色与小屏适配，控件样式交给组件库 |
| `vite.config.ts` | Vue 构建、Element Plus 按需导入和本地 `/api` 代理 |

接口继续使用浏览器原生 fetch。`src/components.d.ts` 在启动或构建时生成，随项目保存，不手工修改。Vite 的代理仅用于开发环境；部署时需要由 Web 服务器把 `/api` 转发到后端。

## 流程编排

流程画布已接入 Vue Flow 核心组件，负责节点拖动、连线、缩放和展示；后端使用 LangGraph 执行串行流程和固定并行分支收敛。暂未增加循环、条件分支或上下文记忆。

各页面通过 Vue Router 切换，当前画布状态保存在页面内，没有引入 Pinia。ChatPanel 通过提交函数复用展示，后续流程调试可接入对应接口。

修改接口、字段或密钥处理方式时，同步维护本文档、[页面文档](src/views/README.md)和 [API 文档](src/api/README.md)。
